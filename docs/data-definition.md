# 데이터 정의서 (core-api)

DB: PostgreSQL (`bigproject`) · 스키마 관리: Hibernate `ddl-auto: update` (Flyway/Liquibase 없음, 엔티티가 스키마의 원본)
대상 테이블: `users`, `consultation`, `attachment`, `ai_analysis` — 전부 `agents/consult`(상담 등록·상담 분석) 기능 범위.
ERD는 [`erd.drawio`](erd.drawio) 참고.

공통 규칙:
- PK는 전부 `BIGINT`, `GENERATED BY DEFAULT AS IDENTITY` (DB auto-increment)
- 감사 컬럼(`created_at`/`updated_at`)은 애플리케이션이 자동 기록 (Spring Data JPA Auditing), 클라이언트가 직접 값을 넣을 수 없음
- `_json` 접미사 컬럼은 전부 `jsonb` — 구조가 사건마다 달라서 컬럼을 안 쪼개고 JSON 그대로 저장
- 분류값 성격의 컬럼(`category`/`type`/`legal_aid_type`/`case_type`/`urgency_level`/`eligibility` 등)은 아직 팀 협의로 값 목록이 확정되지 않아 **자유 문자열**로 열어둠 (enum 아님) — `contracts/README_ai_analysis_contract.md` 참고

## 1. `users` — 상담원/변호사 계정

상담(`consultation`)의 담당자를 나타내는 최소 범위 계정 테이블. 로그인/비밀번호 인증은 아직 미구현.

| 컬럼명 | 데이터타입 | NULL | 기본값 | PK/FK | 설명 |
|---|---|---|---|---|---|
| id | BIGINT | N | identity | PK | 사용자 ID |
| name | VARCHAR(255) | N | - | | 이름 |
| role | VARCHAR(255) | N | - | | 권한 구분. `CONSULTANT`(상담원) \| `LAWYER`(변호사) \| `ADMIN`(관리자) |
| email | VARCHAR(255) | N | - | | 로그인 이메일. UNIQUE 제약 |
| password_hash | VARCHAR(255) | Y | NULL | | 비밀번호 해시. 인증 기능 미구현으로 현재 항상 NULL |
| created_at | TIMESTAMP | N | 생성시각 | | 생성일시 (자동) |
| updated_at | TIMESTAMP | N | 생성시각 | | 수정일시 (자동) |

제약조건: `email` UNIQUE

## 2. `consultation` — 상담 1건 (메인 테이블)

상담 등록 화면(`UploadWorkbench`)에서 생성. 담당 `users`를 반드시 참조.

| 컬럼명 | 데이터타입 | NULL | 기본값 | PK/FK | 설명 |
|---|---|---|---|---|---|
| id | BIGINT | N | identity | PK | 상담 ID |
| user_id | BIGINT | N | - | FK → users.id | 담당 상담원 |
| title | VARCHAR(255) | N | - | | 상담 제목 |
| input_text | TEXT | Y | NULL | | 상담 본문(직접 입력 텍스트, 또는 향후 STT 변환 결과). 녹음파일만 있는 경우 NULL 가능 |
| opponent_name | VARCHAR(255) | Y | NULL | | 상대방 이름 (유사 사건 클러스터링 참고용) |
| status | VARCHAR(255) | N | `RECEIVED` | | 진행 상태. `RECEIVED`(접수) → `ANALYZING`(AI 분석 중) → `COMPLETED`(완료) |
| category | VARCHAR(255) | Y | NULL | | 사건 대분류 (예: 친족/상속/가사소송/가족관계등록 — 등록 화면 선택값 그대로) |
| type | VARCHAR(255) | Y | NULL | | 사건 소분류 (category에 종속된 하위 선택값) |
| legal_aid_type | VARCHAR(255) | Y | NULL | | 법률구조 대상자 유형 (예: `none`/`basicLivelihood`/`nearPoverty`/`disabled`/`wageArrears` 등) |
| eligibility_evidence_submitted | BOOLEAN | Y | `false` | | 법률구조 대상자 증빙서류 제출 여부 (등록 시점 체크) |
| created_at | TIMESTAMP | N | 생성시각 | | 생성일시 (자동) |
| updated_at | TIMESTAMP | N | 생성시각 | | 수정일시 (자동) |

제약조건: `status` CHECK IN (`RECEIVED`,`ANALYZING`,`COMPLETED`) · `user_id` FK

## 3. `attachment` — 상담 첨부파일

상담 1건에 여러 개 첨부 가능 (녹취록/신분증/증빙자료 등). 실제 파일 바이트는 S3에 저장되고, 이 테이블은 메타데이터만 가짐.

| 컬럼명 | 데이터타입 | NULL | 기본값 | PK/FK | 설명 |
|---|---|---|---|---|---|
| id | BIGINT | N | identity | PK | 첨부파일 ID |
| consultation_id | BIGINT | N | - | FK → consultation.id | 소속 상담 |
| file_name | VARCHAR(255) | N | - | | 업로드 당시 원본 파일명 |
| file_type | VARCHAR(255) | N | - | | 파일 종류 (자유 문자열, 예: `녹취록`/`신분증`/`증빙자료`) |
| file_url | VARCHAR(255) | N | - | | 사람이 읽는 참고용 URL (실제 접근/다운로드는 storage_key 기준) |
| storage_bucket | VARCHAR(255) | Y | NULL | | 실제 저장된 S3 버킷명 |
| storage_key | VARCHAR(255) | Y | NULL | | 실제 저장된 S3 오브젝트 키. ai-api STT/문서분석 호출 시 이 값이 그대로 전달됨 |
| content_type | VARCHAR(255) | Y | NULL | | 파일 MIME 타입 (예: `audio/mpeg`) |
| extracted_text | TEXT | Y | NULL | | STT(음성→텍스트)/OCR 결과. 현재 채우는 로직 없어 항상 NULL (예정 필드) |
| uploaded_at | TIMESTAMP | N | 생성시각 | | 업로드일시 (자동) |

제약조건: `consultation_id` FK, ON DELETE는 애플리케이션이 명시적으로 처리 (상담 삭제 시 첨부파일 row + S3 오브젝트 함께 삭제)

## 4. `ai_analysis` — AI 분석 결과

상담 1건이 여러 번 재분석될 수 있다고 보고 1:N(상담 1 : 분석 N)으로 설계 — 재분석 이력을 보존. `contracts/ai_analysis_mock.json` 계약서 필드명과 최대한 1:1로 맞춤.

| 컬럼명 | 데이터타입 | NULL | 기본값 | PK/FK | 설명 |
|---|---|---|---|---|---|
| id | BIGINT | N | identity | PK | 분석 결과 ID (API 응답에서는 `analysis_id`) |
| consultation_id | BIGINT | N | - | FK → consultation.id | 대상 상담 |
| summary | TEXT | Y | NULL | | 분석 요약 (사건유형/긴급도/구조대상 여부를 엮은 한국어 문장) |
| case_type | VARCHAR(255) | Y | NULL | | 사건 유형 (AI가 분류한 값 중 확률 1위, 예: `임금체불`) |
| case_subtype | VARCHAR(255) | Y | NULL | | 사건 세부유형. 계약서 v0.1엔 없던 필드, 추가 결정됨. 현재 `/analyze` 플로우에서는 채우지 않음(NULL) |
| urgency_level | VARCHAR(255) | Y | NULL | | 긴급도 등급 (`상`/`중`/`하`) |
| eligibility | VARCHAR(255) | Y | NULL | | 법률구조 대상 여부 판정 (`대상`/`비대상`/`판단보류`) |
| extracted_json | JSONB | Y | NULL | | 사건 분석 원본 블록 (`case_analysis`: 사건유형 후보 리스트, 긴급도 점수/사유, 첨부파일 추출 상태 등) |
| missing_info_json | JSONB | Y | NULL | | 누락자료 목록 (`missing_items`: 항목/사유/신뢰도/참고서류) |
| checklist_json | JSONB | Y | NULL | | 구조검토 체크리스트 (`relief_review_checklist`: 4대 평가기준 + 변호사용 요약문) |
| recommendation_json | JSONB | Y | NULL | | 추천 판례/법령/유사사례. 현재 `/analyze` 플로우에서는 채우지 않음(NULL) |
| timeline_json | JSONB | Y | NULL | | 사실관계 타임라인. 현재 `/analyze` 플로우에서는 채우지 않음(NULL) |
| cluster_result_json | JSONB | Y | NULL | | 유사사건 클러스터링 결과. 현재 미사용(NULL) |
| estimated_time | VARCHAR(255) | Y | NULL | | 예상 소요기간. 통계 확보 전까지 NULL |
| raw_input_json | JSONB | Y | NULL | | ai-api `/consult/analyze` 호출 시 실제로 보낸 요청 원문 (추적용) |
| created_at | TIMESTAMP | N | 생성시각 | | 분석일시 (자동). `updated_at`은 없음 — 재분석 시 새 row로 쌓임 |

제약조건: `consultation_id` FK, ON DELETE는 애플리케이션이 명시적으로 처리 (상담 삭제 시 함께 삭제)

## 테이블 간 관계 요약

| 관계 | 관계 유형 | 설명 |
|---|---|---|
| users 1 : N consultation | 1:N | 상담원 한 명이 여러 상담을 담당 |
| consultation 1 : N attachment | 1:N, cascade | 상담 삭제 시 첨부파일도 함께 삭제 (JPA `cascade=ALL, orphanRemoval=true`) |
| consultation 1 : N ai_analysis | 1:N, 수동 cascade | 상담 삭제 시 분석 결과도 함께 삭제 (서비스 코드에서 명시적으로 먼저 삭제 — JPA 컬렉션으로 연결돼 있지 않은 단방향 FK) |
