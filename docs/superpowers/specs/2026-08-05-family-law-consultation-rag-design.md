# 가족법 상담사례 RAG 설계

## 1. 목표

대한법률구조공단 법률상담 CSV 네 개를 정규화하여 가족법 상담사례 벡터 인덱스를 구축한다.

상담 입력의 `anonymized_text`를 검색 질의로 사용하고, 관련 법령과 판례에 더해 유사 상담사례를 참고자료로 반환한다.

이번 범위는 다음 네 서비스 카테고리다.

1. 가사소송
2. 가족관계등록
3. 상속
4. 친족

상담사례는 최신 법령이나 판례를 대체하는 법적 근거가 아니라, 유사 사실관계와 설명 방식을 보조하는 참고자료로만 사용한다.

## 2. 원본 데이터

원본 CSV 네 개를 사용한다.

- 대한법률구조공단 법률상담 기본질문답변 1차
- 대한법률구조공단 법률상담 기본질문답변 2차
- 대한법률구조공단 법률상담 사례질문답변 1차
- 대한법률구조공단 법률상담 사례질문답변 2차

원본 인코딩은 CP949로 처리한다.

현재 가족법 범위에 사용할 예상 행 수는 총 1,665건이다.

- 기본질문답변 1차: 360건
- 기본질문답변 2차: 513건
- 사례질문답변 1차: 792건
- 사례질문답변 2차: 0건

사례질문답변 2차는 원본 보관과 구조 검증에는 포함하지만, 현재 가족법 인덱스에는 포함하지 않는다.

## 3. 파일 위치

원본과 처리 결과는 Git에 커밋하지 않고 다음 경로에 둔다.

```text
backend/ai-api/storage/legal_consultations/
├─ raw/
│  ├─ basic_qa_part1_20240731.csv
│  ├─ basic_qa_part2_20240731.csv
│  ├─ case_qa_part1_20240731.csv
│  └─ case_qa_part2_20240731.csv
├─ processed/
│  └─ family_consultations.jsonl
└─ reports/
   ├─ normalization_report.json
   └─ evaluation_report.json
```

벡터 데이터는 기존 `backend/ai-api/storage/chroma`에 새 컬렉션으로 저장한다.

컬렉션 이름은 `legal_consultations`다.

## 5. 정규화 데이터 모델

모든 CSV 행을 다음 공통 구조로 변환한다.

```json
{
  "consultation_id": "consultation-...",
  "source_type": "basic",
  "service_category": "inheritance",
  "legal_path": "상속과유언>상속일반>...",
  "question": "상속을 포기하려면 어떻게 해야 하나요?",
  "answer": "정제된 답변",
  "source_file": "basic_qa_part1_20240731.csv",
  "source_row": 123,
  "source_date": "2024-07-31"
}
```

`consultation_id`는 정규화된 질문, 답변, 소스 유형을 기반으로 한 안정적인 해시 값으로 만든다.

## 6. 정규화 규칙

정규화 순서는 다음과 같다.

1. CP949로 CSV 읽기
2. 파일별 컬럼명을 공통 필드로 변환
3. 앞뒤 공백 제거
4. HTML 태그 제거
5. HTML 엔티티 변환
6. 반복 공백과 줄바꿈 정리
7. 질문 또는 답변이 비어 있는 행 제외
8. 가족법 범위 외 행 제외
9. 동일 질문과 답변 중복 제거
10. 서비스 카테고리 매핑
11. 개인정보 패턴 검사
12. UTF-8 JSONL로 저장
13. 정규화 보고서 생성

개인정보 패턴 검사는 주민등록번호, 전화번호, 이메일 주소와 같이 명백한 패턴을 대상으로 한다.

검사에서 개인정보 후보가 발견되면 자동 삭제하지 않고 보고서에 기록하고 인덱스 생성을 실패시켜 사람이 확인하도록 한다.

## 7. 서비스 카테고리 매핑

### 7.1 가족관계등록

`법률분류`가 `가족관계등록>`으로 시작하는 행을 사용한다.

대표 주제는 등록부정정, 출생신고, 사망신고, 성과 본, 개명, 국적이다.

### 7.2 상속

`법률분류`가 `상속과유언>`으로 시작하는 행을 사용한다.

대표 주제는 상속순위, 상속재산분할, 상속포기, 한정승인, 유언, 유류분이다.

### 7.3 가사소송

`친족` 분류 중 다음 주제를 가사소송으로 매핑한다.

- 이혼
- 재산분할
- 위자료
- 혼인무효
- 혼인취소
- 사실혼
- 양육비
- 양육자 지정
- 면접교섭
- 친권자 지정 또는 변경
- 사전처분
- 이행명령

### 7.4 친족

`친족` 분류 중 가사소송에 매핑되지 않은 다음 주제를 친족으로 매핑한다.

- 입양과 파양
- 친생자관계
- 친생부인
- 인지
- 친권상실
- 후견
- 부양
- 실종
- 부모와 자녀 관계

분류 규칙은 문자열 포함 여부만 곳곳에 직접 작성하지 않고, 하나의 명시적인 매핑 테이블로 관리한다.

## 8. 상담 문서와 청크

청크 설정은 기존 법령과 판례 인덱스 정책을 따른다.

- 임베딩 모델: `intfloat/multilingual-e5-small`
- 임베딩 차원: 384
- 문서 접두사: `passage:`
- 검색 접두사: `query:`
- 청크 크기: 800자
- 중첩: 120자
- 임베딩 정규화: 기존 정책 유지

모든 답변 청크에는 원래 질문과 법률분류를 반복해서 포함한다.

```text
passage:
분류: 상속과유언 > 상속포기
질문: 부모가 빚을 남기고 사망했습니다.
답변: ...
```

검색 결과는 동일한 `consultation_id`에서 여러 청크가 검색되더라도 상담사례당 최대 한 건만 반환한다.

## 9. 검색과 재정렬

검색기는 최소 15개 이상의 후보 청크를 가져온 뒤 재정렬한다.

재정렬은 다음 신호만 사용한다.

- 벡터 유사도
- 질문과 사례 질문의 어휘 일치
- 서비스 카테고리 일치
- 기본질문과 사례질문 유형

최종 반환 수는 최대 3건이다.

선택 우선순위는 다음과 같다.

- 사례질문답변 최대 2건
- 기본질문답변 최대 1건
- 한 유형이 부족하면 다른 유형으로 채움

결과에는 전체 답변이 아니라 최대 1,000자의 `answer_excerpt`를 포함한다.

## 10. API 응답과 프롬프트

상담 분석 응답에 `related_consultations`를 추가한다.

각 결과는 다음 필드를 가진다.

- `consultation_id`
- `source_type`
- `service_category`
- `legal_path`
- `question`
- `answer_excerpt`
- `similarity`
- `source_date`

LLM 프롬프트에 전달하는 순서는 다음과 같다.

1. 관련 법령
2. 관련 판례
3. 유사 상담사례

상담사례 구역에는 다음 문구를 표시한다.

```text
[유사 상담사례 — 법적 근거가 아닌 참고자료]
```

## 11. 개인정보와 장애 처리

다음 경계를 반드시 유지한다.

- 검색 질의는 `anonymized_text`만 사용
- `summary`, `details`, 첨부파일 원문은 검색에 사용하지 않음
- 마스킹 결과가 없을 때 원문으로 폴백하지 않음
- 익명화 텍스트가 없으면 빈 배열 반환
- 상담사례 인덱스가 없거나 검색이 실패하면 빈 배열 반환
- 상담사례 검색 실패가 전체 상담 분석을 중단시키지 않음

원본 CSV, 정규화 JSONL, Chroma 데이터, 평가 보고서는 Git에 커밋하지 않는다.

## 12. 테스트 전략

TDD 방식으로 구현한다.

### 12.1 로더

- CP949 디코딩
- 파일별 예상 컬럼
- 파일별 전체 행 수
- 누락 파일 오류
- 잘못된 인코딩 오류

### 12.2 정규화

- HTML 제거
- 공백 정리
- 빈 질문과 답변 제외
- 가족법 범위 필터
- 서비스 카테고리 매핑
- 중복 제거
- 개인정보 패턴 차단
- 안정적인 ID 생성

### 12.3 문서와 청크

- 질문이 모든 청크에 포함됨
- 800자와 중첩 120자
- 빈 청크 없음
- 중복 청크 없음
- 필요한 메타데이터 유지

### 12.4 인덱스와 검색

- `legal_consultations` 컬렉션 사용
- 저장 수와 생성 청크 수 일치
- 다른 Chroma 컬렉션 유지
- 동일 상담 중복 제거
- 사례 2건과 기본 1건 균형
- 빈 질의 검증
- 검색 실패 시 빈 결과

### 12.5 통합

- `related_consultations` 응답 계약
- `anonymized_text`만 검색기로 전달
- 원문 폴백 금지
- 상담사례 실패 시 법령과 판례 결과 유지
- Python과 Java DTO 계약 일치

## 13. 검색 품질 평가

원본 질문을 그대로 복사하지 않고 실제 사용자 표현으로 바꾼 평가 질의 12개를 사용한다.

- 가사소송 3개
- 가족관계등록 3개
- 상속 3개
- 친족 3개

품질 기준은 다음과 같다.

- 카테고리 Top-3 적중: 12/12
- 관련 용어 Top-3 적중: 10/12 이상
- 동일 상담 중복: 0건
- 가족법 외 명백한 잡음: 0건
- 검색 실패: 0건

Top-1 적중률은 기록하지만 이번 PR의 필수 게이트로 사용하지 않는다.

- 개인정보 후보 0건
- `legal_consultations` 컬렉션 생성
- 생성 청크 수와 저장 수 일치
- 상담사례 Top-3 검색

## 15. 범위 밖

- 상담사례를 법령이나 판례보다 우선하는 재정렬
- 별도의 LLM 요약 인덱스 생성
- 새 임베딩 모델 도입
- 외부 검색 API 추가
- 원본 CSV를 Git 또는 배포 이미지에 포함
