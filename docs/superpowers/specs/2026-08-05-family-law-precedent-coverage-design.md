# 가족법 판례 RAG 카테고리 보강 설계

## 1. 목적

판례 RAG가 서비스의 네 법률 카테고리를 최소한의 품질 기준으로 지원하도록
수집 범위와 검색 평가를 보강한다.

대상 카테고리는 다음과 같다.

1. 가사소송
2. 가족관계등록
3. 상속
4. 친족

이번 작업은 PR 전 최소 보강 작업이다.

## 2. 현재 상태

법령 인덱스에는 다음 법률이 포함되어 있어 네 카테고리의 법령 기반은 이미 존재한다.

- 민법
- 가사소송법
- 가족관계의 등록 등에 관한 법률
- 민사소송법
- 민사집행법

판례 수집은 이혼, 재산분할, 양육비, 친권, 면접교섭, 상속, 유류분,
친생자, 인지청구, 친생부인, 가족관계등록, 부양료, 성년후견 등을 포함한다.

그러나 가족관계등록과 친족의 일부 주요 사건 유형이 명시적 검색어에 없고,
현재 평가 질의도 이혼·양육·상속 중심이다.

## 3. 작업 범위

다음 항목만 수정한다.

- 판례 제목 검색 키워드 확장
- 판례 본문 검색 키워드 확장
- 참조 법률 검색 앵커 확장
- 카테고리별 평가 질의 추가
- 관련 단위 테스트 추가
- 판례 인덱스 재생성
- 검색 품질 재평가

다음 항목은 수정하지 않는다.

- 상담 API 응답 구조
- anonymized_text 개인정보 경계
- 법령 인덱스 대상 법률
- 임베딩 모델
- 청크 크기와 오버랩
- Chroma 컬렉션 이름
- legal_category 메타데이터와 카테고리 필터 검색

## 4. 판례 수집 키워드 보강

### 4.1 가사소송

기존 이혼·재산분할·양육비·친권·면접교섭 키워드에 다음을 추가한다.

- 혼인무효
- 혼인취소
- 사실혼

### 4.2 가족관계등록

다음 키워드를 명시적으로 추가한다.

- 가족관계등록부
- 가족관계등록부정정
- 등록부정정
- 출생신고
- 혼인신고
- 이혼신고
- 사망신고
- 인지신고
- 성본변경
- 성과본변경

너무 일반적인 `등록`, `정정`, `신고` 단독 문자열은 사용하지 않는다.
행정·부동산·법인등록 사건의 오탐을 줄이기 위함이다.

### 4.3 상속

기존 상속·유류분·상속포기·한정승인·상속회복·기여분·특별수익에
다음을 추가한다.

- 상속승인
- 상속결격
- 상속재산관리인
- 특별연고자
- 유언
- 유언효력
- 유언집행
- 유증

### 4.4 친족

기존 친생자·인지청구·친생부인·부양료·성년후견에 다음을 추가한다.

- 입양
- 파양
- 친생관계존부확인
- 친생자관계존부확인
- 친생자관계부존재확인
- 친권자지정
- 친권상실
- 미성년후견
- 후견개시
- 부양청구
- 실종선고
- 부재자재산관리

`인지` 단독 키워드는 인지세 등 다른 법률 분야의 오탐 가능성이 있어 사용하지 않는다.

## 5. 검색 작업 구성

### 5.1 제목 검색

모든 확장 키워드는 대법원과 하급심 제목 검색에 사용한다.

### 5.2 본문 검색

검색 작업 수와 API 호출량을 과도하게 늘리지 않도록
대표성이 높은 다음 항목만 본문 검색에 추가한다.

- 가족관계등록부정정
- 출생신고
- 입양
- 파양
- 친생자관계
- 인지청구
- 성년후견
- 미성년후견
- 유언
- 상속포기
- 한정승인

### 5.3 참조 법률 검색

기존 가사소송법 및 가족관계등록법 전체 참조 검색은 유지한다.

민법·민사소송법·민사집행법 참조 검색의 앵커에는 다음을 추가한다.

- 가족관계등록부정정
- 입양
- 친생자관계
- 인지청구
- 유언

기존 상속·유류분·후견 앵커는 유지한다.

## 6. 관련성 필터

기존 필터 정책을 유지한다.

- 사건종류에 `가사`가 포함되면 수집
- 그 외 사건은 사건명에 도메인 키워드가 있을 때 수집
- 세금·행정·특허·형사 잡음 제목은 제외
- 판례 ID 기준 중복 제거

보강 후 새 키워드 때문에 수집되는 사건 중 명백한 행정·조세 사건이 발견되면
구체적인 사건명 제외어만 추가한다.

광범위한 일반 단어 제외 규칙은 추가하지 않는다.

## 7. 평가 질의

기존 다섯 질의를 유지한다.

### 7.1 가사소송

- 재산분할
- 양육비
- 면접교섭

### 7.2 가족관계등록

다음 두 질의를 추가한다.

1. 가족관계등록부에 잘못 기록된 부모 정보를 정정하고 싶다.
   - 기대어: 가족관계등록부정정, 등록부정정, 가족관계등록

2. 출생신고가 누락되어 가족관계등록부를 바로잡고 싶다.
   - 기대어: 출생신고, 가족관계등록부정정, 가족관계등록

### 7.3 상속

기존 유류분과 상속포기·한정승인 질의를 유지하고 다음을 추가한다.

1. 사망한 부모가 남긴 유언의 효력을 다투고 싶다.
   - 기대어: 유언, 유언효력, 유증

### 7.4 친족

다음 세 질의를 추가한다.

1. 양부모와의 입양 관계를 종료하고 싶다.
   - 기대어: 파양, 입양

2. 법률상 아버지가 친아버지가 아니어서 친생자 관계를 다투고 싶다.
   - 기대어: 친생부인, 친생자관계부존재확인, 친생자관계존부확인

3. 치매가 심한 부모를 위해 성년후견 개시를 신청하고 싶다.
   - 기대어: 성년후견, 후견개시

최종 평가 질의 수는 총 11개다.

## 8. 품질 기준

PR 전 다음 조건을 모두 만족해야 한다.

- 전체 Top-5 적중: 11개 중 9개 이상
- 가사소송: 3개 중 2개 이상
- 가족관계등록: 2개 중 1개 이상
- 상속: 3개 중 2개 이상
- 친족: 3개 중 2개 이상
- 중복 판례 결과가 발생한 질의: 0개
- 신규 평가 질의 Top-3에 명백한 조세·행정·형사 잡음이 없어야 함

Top-1 적중률은 기록하지만 이번 PR의 차단 조건으로 사용하지 않는다.

## 9. 인덱스 재생성

수집 키워드가 변경되므로 기존 판례 인덱스를 재생성한다.

재생성 후 다음을 확인한다.

- 상세조회 실패 0건
- 저장 청크 수와 고유 판례 수 기록
- 기존 319건, 3,298청크보다 감소하지 않는지 확인
- 감소하면 코드 문제로 단정하지 않고 API 응답 범위와 날짜 조건부터 조사

법령 인덱스는 다시 만들지 않는다.

## 10. 테스트 전략

TDD 순서로 진행한다.

1. 새 키워드와 검색 작업을 요구하는 실패 테스트 추가
2. 평가 질의 11개와 카테고리 집계를 요구하는 실패 테스트 추가
3. 수집기 및 평가기 최소 수정
4. 관련 단위 테스트 통과
5. Python 전체 테스트 통과
6. 판례 인덱스 재생성
7. 실제 검색 평가 실행
8. 품질 기준 확인 후 커밋

## 11. 완료 조건

다음 조건을 충족하면 보강 완료로 판단한다.

- 네 카테고리의 명시적 판례 검색어가 존재함
- 네 카테고리 모두 평가 질의를 가짐
- 품질 기준을 통과함
- 전체 Python 테스트가 통과함
- core-api 테스트가 계속 통과함
- anonymized_text 전용 RAG 입력 규칙이 유지됨
- 작업 브랜치가 master보다 뒤처지지 않음

- 판례별 legal_category 메타데이터 저장
- 상담 카테고리를 이용한 검색 필터 또는 가중치
- 카테고리별 평가 데이터 확대
- Top-1 재정렬 개선
